# RE:AD — платформа активного чтения

**RE:AD** — это набор из трёх автономных веб-приложений для осмысленного изучения текста
и создания заданий: студенческий плеер чтения с тестированием, визуальный редактор
XML-заданий с публикацией и AI-ассистентом, а также служебная страница преподавателя
для извлечения вопросов и правильных ответов.

Все приложения работают **полностью на стороне клиента** (чистые HTML/CSS/JS, без сборки
и серверной части) и могут размещаться на любом статическом хостинге, например GitHub Pages.

## 🎓 Приложение студента (плеер чтения)

Одностраничное приложение (`/index.html`) проводит студента по маршруту:
**авторизация → чтение фрагментов с промежуточным тестом → финальный тест → результаты.**

### Загрузка задания

| Способ | Как работает |
|---|---|
| 📁 Выбор XML-файла | Кнопка «Выбрать XML файл» на экране авторизации (`FileReader`) |
| 🔗 URL-параметр `file` | `index.html?file=https://…/task.xml` — задание загружается автоматически при старте (`fetch`) |
| 👤 ФИО студента | Обязательное поле; проверяется перед стартом |

После успешной загрузки активируются кнопки **«Начать чтение»**, **«Сдать финальный тест
без чтения»** и **«Для преподавателя»**, отображается тема теста (`<topicName>`).
С этого момента начинается отсчёт общего времени сдачи.

### Режим чтения

- Текст показывается **по фрагментам**; прогресс отображается точками-пипсами в шапке
  (пройдено / текущий / осталось).
- **Таймер-полоса** меняет цвет по нормативам фрагмента:
  - 🟢 до `timeExcellent` секунд — «отличное» время;
  - 🟡 после `timeExcellent` и до `timeGood` — «хорошее»;
  - 🔴 после `timeGood` — время превышено.
- Кнопка **«Готов к вопросам»** останавливает таймер и переводит к промежуточному тесту
  (затраченное время фрагмента сохраняется в статистику).

### Промежуточный тест

Обучающий режим сразу после прочтения фрагмента:

- Вопросы выводятся **по одному** (выбор варианта или свободный ввод).
- Неверный ответ разрешает **повторную попытку**; счётчик ошибок виден в шапке
  (`Ошибки: N/2`).
- При достижении лимита **`MAX_QUIZ_ERRORS = 2`** ошибки студент принудительно
  возвращается к перечитыванию того же фрагмента.
- После верного ответа — автоматический переход к следующему вопросу
  (пауза 800 мс); счётчик ошибок при этом **сбрасывается**.
- Все вопросы фрагмента пройдены → переход к следующему фрагменту;
  фрагмент помечается как пройденный (`state.readingProgress`).

### Финальный тест

Запускается после прохождения всех фрагментов (или досрочно — см. ниже):

- Включает **все вопросы всех фрагментов подряд** со сквозной нумерацией.
- **Одна попытка на вопрос**: после ответа варианты блокируются, правильный вариант
  подсвечивается зелёным, неверно выбранный — красным (пауза 1200 мс до следующего вопроса).
- Перед первым вопросом показывается приветственное окно «Финальный тест».
- Все ответы записываются в протокол (`stage: 'final'`) и попадают в итоговую ведомость.

### Досрочное завершение

Кнопка в шапке меняет назначение в зависимости от режима:

| Режим | Кнопка | Действие |
|---|---|---|
| Чтение | **«Завершить чтение»** | Если пройдено **более 60 %** заданий чтения — сразу открывается экран результатов с оценкой «3»; иначе запускается финальный тест |
| Любой тест | **«Завершить тест»** | Немедленный переход к результатам по уже отвеченным вопросам |

Также на экране авторизации есть **«Сдать финальный тест без чтения»** — мгновенный
переход к финальному тестированию (оценка считается только по нему).

### Проверка ответов (Jaro-Winkler)

- **Choice**: совпадает текст выбранного варианта с `<option correct="true">`.
- **Input**: нестрогая проверка — ответ приводится к нижнему регистру и сравнивается
  с эталоном алгоритмом **Jaro-Winkler**; ответ засчитывается, если схожесть
  ≥ порога `similarity` вопроса (по умолчанию **0.8**). Это прощает опечатки
  и разные падежи коротких ответов.

### Система оценивания

Итоговая оценка считается по доле верных ответов **финального теста**
(`calculateGrade`):

| Условие | Оценка |
|---|---|
| ≤ 60 % верных | **2** |
| > 60 % верных | **3** |
| ≥ 70 % верных | **4** |
| ≥ 85 % верных | **5** |

Дополнительно: завершение чтения при прохождении более 60 % фрагментов даёт оценку **3**
без финального теста («3» — потолок, «4» и «5» — только через тестирование).
Время чтения влияет на цветовую индикацию таймера, но не снижает оценку автоматически.

### Экран результатов

- Верхний блок: **ФИО студента, тема теста, дата и время сдачи, затраченное время**
  (формат `Чч Мм Сс`; время считается с момента загрузки первого экрана с заданием).
- Круг с итоговой оценкой, карточки статистики: время и количество ошибок.
- Таблица «Результаты финального теста»: вопрос → ответ студента → статус
  (Верно / Ошибка). Промежуточные исправленные ошибки в отчёт не попадают.
- Кнопка **«Для преподавателя»** открывает страницу `/right_answer/` с тем же XML
  (`?xml=<тот же file>`), если задание было загружено по URL.

## ✏️ Редактор заданий

SPA `/editor/index.html` для создания и правки XML-тестов формата `<readingTest>`.
Интерфейс: панель XML слева, редактор справа, модальные окна настроек, служебная строка
статуса и toast-уведомления. Границу панелей можно перетаскивать мышью.

### Работа с фрагментами и вопросами

- **Навигация**: кнопки «← Предыдущий / Следующий →», добавление «+ Фрагмент»,
  удаление текущего фрагмента.
- **Нормативы времени** каждого фрагмента: поля `Time Excellent` и `Time Good`
  (по умолчанию 60 / 90 секунд).
- **Текст фрагмента**: многострочное поле.
- **Вопросы двух типов**:
  - **+ Вопрос на выбор (choice)** — список вариантов, правильный отмечается радио-кнопкой;
  - **+ Вопрос на ввод (input)** — поле правильного текстового ответа.

### XML-панель и двусторонняя синхронизация

- Любые изменения формы **мгновенно отражаются в XML** (генерация `generateXml()`).
- Ручные правки XML применяются к форме кнопкой **«Применить ▶»**
  (с подтверждением и последующей записью в файл, если включена работа с диском).
- **«Копировать»** — XML в буфер обмена.

### Метаданные теста

Кнопка **«👤 Метаданные теста»** задаёт поля, сохраняемые в XML и подставляемые
в имя файла: `<topicName>`, `<author>`, `<university>`, `<discipline>`,
`<targetAudience>`. Метаданные хранятся как шаблон в `localStorage`.

### Файл на диске и автосохранение

- **«📂 Загрузить из файла»** — открытие XML с диска (File System Access API,
  fallback на `<input type="file">` в Firefox/Safari). Выбранный файл становится
  целевым для всех последующих сохранений.
- **«💾 Сохранить в файл»** — запись в выбранный файл без диалогов; при отсутствии
  поддержки FSAA — обычное скачивание.
- **Автосохранение** (переключатель в настройках): дебаунс **1500 мс** после изменений,
  запись в уже выбранный файл на диске.
- Индикатор несохранённых изменений и отметка времени последнего сохранения на диск.

### Проверка готовности и панель «Обзор»

- Перед публикацией выполняется проверка `findAnswerIssues()`: у всех `choice`-вопросов
  должен быть выбран правильный вариант, у всех `input` — непустой ответ.
- Рядом с кнопкой публикации показывается предупреждение
  «⚠ нет правильного ответа: N вопр.».
- **«👁 Обзор»** — правая панель быстрого просмотра всех вопросов с правильными ответами.

### Публикация на GitHub Gist и GitVerse

Кнопка **«🚀 Публикация ▾»** предлагает два сервиса (нужен токен из настроек):

| Сервис | Поведение |
|---|---|
| **GitHub Gist** | Первое сохранение создаёт gist (файл `reading_test.xml`), далее gist обновляется (PATCH API). Можно создавать новый gist вручную |
| **GitVerse** | Публикация/обновление файла в репозитории через API v2 (автоподбор репозитория `reading-tests`, base64-кодирование содержимого, коммит с описанием) |

После публикации:

- формируется **ссылка на задание** вида
  `https://tregubovvn.github.io/rt_v2/index.html?file=<raw-url>` и копируется в буфер;
- **«☁️ Загрузить из Gist»** — обратная загрузка задания по ID или ссылке gist;
- **«Открыть задание»** — синхронизирует свежую версию в gist и открывает плеер
  по готовой ссылке (с предварительной проверкой готовности).

### Интеграция с DeepSeek AI

Кнопка **«✨ Отправить DeepSeek»** отправляет содержимое XML-панели вместе
с активным промптом в модель и возвращает результат обратно в XML и редактор.

- **Режимы (промпты)** выбираются в выпадающем списке: «Абзацы», «Предложения»
  и пользовательские.
- К промпту автоматически добавляются технические требования: ответ — только полный
  XML `<readingTest>…</readingTest>` с сохранением метаданных и финальным маркером
  `[RE:AD-TEST-READY]`.
- Если модель не завершила ответ (нет маркера/закрытых тегов), редактор **сам просит
  продолжить** — до 3 дополнительных запросов.
- Ответ, не являющийся XML, открывается в **окне результата** с кнопками
  «Копировать», «Закрыть», «Отправить в DeepSeek» (можно уточнить запрос).
- Без токена DeepSeek: промпт + XML копируются в буфер и открывается
  `chat.deepseek.com` — вставка вручную.
- На время запроса интерфейс блокируется индикатором прогресса с этапами обработки.

### Управление промптами

Все промпты хранятся в **одном GitHub Gist в Markdown-формате** (каждый промпт — секция `## Название`):

- **«📝 Промпты…»** — список всех промптов, добавление своих, удаление,
  перезагрузка из Gist, **«💾 Сохранить все в Gist»** (back-up своих промптов);
- **«✎ Редактор»** — редактирование активного промпта (правки живут локально
  в `localStorage` до сохранения в Gist);
- **«↻ Gist»** — перезагрузка актуального текста промпта из Gist;
- **«📋 Копировать»** — копирование активного промпта в буфер;
- ссылка на Gist с промптами настраивается в окне «Промпты…».

### Настройки и токены

Кнопка **«⚙ Настройки»**: токены **GitHub** (fine-grained, право *Gists: Read and write*),
**DeepSeek** (platform.deepseek.com → API Keys) и **GitVerse**. Все токены, метаданные,
флаг автосохранения и активный режим AI хранятся только в `localStorage` браузера
и никуда не отправляются, кроме соответствующих API.

## 🔑 Страница преподавателя (извлечение ответов)

Self-contained файл `/right_answer/index.html`: разбирает XML-тест и формирует
текстовый список всех вопросов с правильными ответами. Работает офлайн, без зависимостей.

### Три режима ввода XML

| № | Режим | Пароль |
|---|---|---|
| 1 | **Вставка в поле** — кнопка «Вставить» (Clipboard API), `Ctrl+V` (автообработка) или **drag-and-drop файла** в окно | не требуется |
| 2 | **XML прямо в URL** — `index.html?xml=<encodeURIComponent(XML)>` | не требуется |
| 3 | **Ссылка на XML-файл** — `index.html?pwd=1234&xml=https://…/test.xml` (загрузка XHR) | **требуется** |

Если вставленный текст похож на тест (`<readingTest`, `<fragment`, `<question`), он
разбирается и заменяется списком; обычный текст вставляется как есть с предупреждением.

### Защита паролем

- Пароль жёстко вшит в код: константа `PASSWORD` (по умолчанию `1234`),
  число попыток — `MAX_ATTEMPTS = 3`.
- Требуется **только** для режима 3 (загрузка файла по ссылке). Неверный/отсутствующий
  `pwd` в URL вызывает диалог ввода; после отказа доступ блокируется до перезагрузки.
- ⚠️ Защита символическая: пароль виден в исходном коде страницы.

### Режимы отображения и интерфейс

- **«Показать / Скрыть текст фрагментов»** — мгновенное переключение вывода
  (только вопросы+ответы или вместе с полным текстом каждого фрагмента)
  без повторной вставки XML — разобранные данные кэшируются в памяти.
- **Защита ручных правок**: если результат отредактирован вручную, при переключении
  режима запрашивается подтверждение перегенерации.
- **«Копировать»** — результат в буфер (`navigator.clipboard` с fallback на
  `document.execCommand('copy')`).
- **Размер шрифта результата**: кнопки A− / A / A+ (10–30 px, шаг 2, сохраняется в `localStorage`).
- Строка статуса: зелёные сообщения об успехе, красные об ошибках, автоскрытие через 6 с.

Пример вывода (сквозная нумерация по всему тесту):

```text
ТЕМА: Название темы

=== ФРАГМЕНТ 1 ===
1. Текст вопроса? (Правильный вариант)
2. Напишите термин. (ключевое_слово)

=== ФРАГМЕНТ 2 ===
3. Вопрос из второго фрагмента? (Правильный вариант 2)
```

Особенности распознавания: принимаются `correct="true" | "1" | "yes" | "да"`
(без учёта регистра); несколько правильных вариантов выводятся через ` / `;
отсутствующий ответ помечается `(ответ не найден)`; атрибуты времени в вывод не попадают.

## 📄 Формат файла задания (XML)

Единый формат для всех трёх приложений:

```xml
<readingTest>
    <topicName>Название темы</topicName>
    <author>Иванов И. И.</author>
    <university>Название университета</university>
    <discipline>Дисциплина</discipline>
    <targetAudience>Группа 101</targetAudience>

    <fragment timeExcellent="30" timeGood="60">
        <text>Текст первого фрагмента для чтения (рекомендуется 60–90 слов).</text>
        <questions>
            <!-- Вопрос с выбором ответа -->
            <question type="choice">
                <text>Текст вопроса?</text>
                <options>
                    <option>Неправильный вариант</option>
                    <option correct="true">Правильный вариант</option>
                    <option>Ещё один неправильный</option>
                </options>
            </question>

            <!-- Вопрос со свободным вводом -->
            <question type="input" similarity="0.8">
                <text>Напишите термин (одно слово).</text>
                <answer>ключевое_слово</answer>
            </question>
        </questions>
    </fragment>

    <!-- следующие <fragment> ... -->
</readingTest>
```

| Тег / атрибут | Обязательно | Описание |
|---|---|---|
| `<readingTest>` | да | Корневой элемент |
| `<topicName>` | нет | Тема теста (отображается в плеере, попадает в отчёт) |
| `<author>`, `<university>`, `<discipline>`, `<targetAudience>` | нет | Метаданные (создаются редактором, сохраняются при AI-генерации) |
| `<fragment>` | да (≥1) | Контейнер фрагмента текста и вопросов |
| `timeExcellent` | нет | Секунды до перехода таймера в жёлтый (по умолчанию 120 в плеере, 60 в редакторе) |
| `timeGood` | нет | Секунды до перехода таймера в красный (по умолчанию 200 в плеере, 90 в редакторе) |
| `<text>` | да | Содержимое фрагмента / формулировка вопроса |
| `<question type="choice\|input">` | да | Тип вопроса |
| `similarity` | нет | Порог схожести Jaro-Winkler для `input`-ответов (по умолчанию 0.8) |
| `<option correct="true">` | да | Правильный вариант (допустимы `"1"`, `"yes"`, `"да"`) |
| `<answer>` | да | Эталонный ответ для `input` (регистр не учитывается) |

Шаблон промпта для массовой генерации заданий нейросетью — в файле `prompt_gist.md`.

## ⚙️ Установка и запуск

Приложения не требуют сборки, npm-пакетов и сервера.

### Локальный запуск

```bash
git clone https://github.com/tregubovvn/rt_v2.git
cd rt_v2
# Вариант А: просто открыть index.html / editor/index.html / right_answer/index.html в браузере
# Вариант Б (рекомендуется, чтобы работал fetch по file:// без CORS):
python3 -m http.server 8080
# → http://localhost:8080/index.html
```

### Размещение на GitHub Pages

Запушить репозиторий и включить Pages — все три приложения будут доступны по путям
`/index.html`, `/editor/`, `/right_answer/`.

### Типовой рабочий процесс

1. Преподаватель открывает **редактор**, создаёт задание (или генерирует его через DeepSeek),
   сохраняет на диск и **публикует** — получает ссылку вида
   `https://…/rt_v2/index.html?file=https://gist.githubusercontent.com/…/reading_test.xml`.
2. Студент переходит по ссылке, вводит ФИО и проходит чтение с тестированием.
3. Преподаватель открывает страницу **`/right_answer/?xml=<ссылка>`** (или кнопку
   «Для преподавателя» в плеере) и получает список всех вопросов с правильными ответами.

## 🧰 Технические детали

- **Стек**: HTML5, CSS3 (Flexbox/Grid, CSS Variables, `clamp()` для адаптивных шрифтов,
  эффект Glassmorphism), Vanilla JavaScript (ES6+, ES-модули в плеере).
- **Модули плеера**: `js/app.js` (состояние и логика), `js/xml-parser.js` (`DOMParser`,
  валидация, значения по умолчанию), `js/jaro-winkler.js` (алгоритм нечёткого сравнения).
- **API**: GitHub REST (Gists), GitVerse API v2, DeepSeek Chat Completions,
  File System Access API, Clipboard API, `localStorage`.
- **Безопасность**: всё выполняется на клиенте; ФИО студента никуда не передаются;
  токены хранятся только в `localStorage`; вывод пользовательских строк экранируется
  (`escapeHtml` / `escapeXml`).
- **Совместимость**: современные Chrome, Firefox, Edge, Safari. Для загрузки файлов
  по ссылке используйте `http(s)://` (на `file://` запросы блокирует CORS).
- `package.json` содержит только dev-зависимость `jsdom` (для тестов вне браузера);
  runtime-зависимостей нет.

### Известные ограничения

| Ограничение | Причина | Обход |
|---|---|---|
| Кнопка «Вставить» может не работать | Буфер обмена доступен только по HTTPS/с разрешения | Использовать `Ctrl+V` или drag-and-drop |
| Загрузка по ссылке блокируется на `file://` | Политика CORS | Открывать через `http://`-сервер |
| Большие XML не помещаются в URL | Ограничение длины URL | Вставка в поле или ссылка на файл |
| Автосохранение в файл — только Chromium | File System Access API | Firefox/Safari: сохранение через скачивание |
| Пароль страницы преподавателя виден в коде | Клиентская проверка | Осознанно: барьер от случайного доступа |
